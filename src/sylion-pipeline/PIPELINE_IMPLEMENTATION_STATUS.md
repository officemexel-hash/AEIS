## Limitations

> Section required per Sprint 1b backlog item #19.

### What the pipeline does NOT do

1. **No automatic code generation** — agents analyze, audit, and produce patches/configs, but do not generate application code from scratch.
2. **No automatic deployment to production** — `pixel_deployer` and `router_deployer` push to test devices only (`/data/local/tmp/sylion/`). Production deploy requires manual steps.
3. **No runtime monitoring** — pipeline runs as a batch process. `stream_monitor` checks streaming during pipeline execution, not as a persistent service.
4. **No automatic rollback** — if patches break tests, pipeline halts for human decision. No automated git revert.
5. **No multi-repo support** — single workspace assumed. Cross-repo dependencies must be resolved externally.
6. **No secrets management** — API keys loaded via `.env`/environment. No vault integration.
7. **No incremental audits** — each pipeline run is a full audit. No delta/diff-only mode yet.
8. **No physical SDR hardware validation** — SDR agents generate configs and test plans but require HackRF/LimeSDR hardware to be connected for actual RF tests. ZMQ mode is available as simulation fallback.
9. **No iOS/Android (non-GrapheneOS) support** — Pixel 8 with GrapheneOS is the only mobile target. Standard Android/iOS deployment is not supported.
10. **No cloud deployment** — pipeline assumes local execution with physical devices via USB/Ethernet.
