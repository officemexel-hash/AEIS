## Severity rules

- `P0`: blocks runtime startup, login/setup, data integrity, governance safety, secret exposure.
- `P1`: blocks primary operator flow or creates false PASS/false approval.
- `P2`: partial flow break, missing live data, broken action, wrong state after click.
- `P3`: visual/wording/documentation issue that does not break action.
- `P4`: polish backlog.

## Required bug evidence

Each real bug must include:

- exact route and viewport;
- operator steps;
- expected result;
- actual result;
- screenshot or log/probe path;
- browser console/network error if applicable;
- backend log excerpt if applicable;
- fix commit/diff summary;
- two retest records before freeze.
